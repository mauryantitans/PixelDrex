• 16×16 sprite = 256 questions = 1 request (up to 512 per request, 8 in flight)

• Each part's color is one more question in the same request
• Parts, not colors: parts carry meaning, so Drex knows a nose cone goes on top

RESOLUTION WITHOUT COORDINATES
Drex is strong at local judgments and weak at exact positions, so we never ask about row 27 of 32.
1. Paint the clean 16×16 part layout in one request.
2. Double it. Every edge pixel asks Drex, from its 8 neighbours only:
I'm 'sheet'. North: sheet · East: empty ·
South: mouth · West: sheet … Which should I
be so the outline is smooth?
3. Identical neighbourhoods share one question: about 1 Drex call per doubling, and the same trick smooths backgrounds.

ANIMATION
MOTION AND CHANGE ARE DECISIONS TOO
For each of 16 frames, in one request per sprite:
score x · y · size · tilt (leaning left … right) · shape (stretched … squashed)
choice "Which pose is the tree in during frame 7?" sapling · young tree · full tree
Poses: 3 shapes, Drex picks one per frame
Squash and stretch, decided by Drex
A score question returns an expected value, so paths come out sub-pixel smooth: no keyframes, no physics code. Shape-changing sprites get 2–4 poses painted with shared colors in one shared frame, so nothing jumps.

THE EXTENSION · DREX LIFE
THE WORLD LEARNS ITS PHYSICS
SHARED QUESTIONS
A cell asks with its state and neighbour counts: “I'm a tree with 2 burning neighbours. What am I next?” Cells in the same situation share it.
CACHED ACROSS FRAMES
Situations repeat, so answers are reused. A 32×32 × 40-frame fire: 41,984 cell decisions from 1,832 questions, 22 s, under 2¢.
SAMPLED, NOT ARGMAX
The next state is sampled from Drex's calibrated probabilities (T = 0.8), so “lightning rarely strikes” really is rare.
